## Background: What is SynthID?

SynthID is Google DeepMind's invisible watermarking system embedded into AI-generated content from Google products (Gemini, Imagen, Veo, Lyria). Unlike metadata tags (EXIF, C2PA) which can be trivially stripped, SynthID modifies the actual pixel values of images in a way that is:

- **Invisible** to the human eye
- **Robust** against JPEG compression, cropping, resizing, and filtering
- **Detectable** algorithmically via spectral analysis

Google keeps the official SynthID detector proprietary. As of early 2026, the "SynthID Detector" portal is limited to journalists and media professionals on a waitlist. There is no public API.

However, researchers have reverse-engineered the watermark's spectral structure, enabling independent detection without Google's neural network decoder.

## How SynthID Watermarking Works

SynthID does **not** use simple LSB (Least Significant Bit) replacement. It uses a spread-spectrum, phase-encoding technique:

```
┌─────────────────────────────────────────────────────┐
│             SynthID Encoder (at generation time)    │
├─────────────────────────────────────────────────────┤
│                                                     │
│  1. Select carrier frequencies in frequency space   │
│     e.g., (14,14), (126,14), (98,-14), ...          │
│                                                     │
│  2. Assign fixed phase values to each carrier       │
│     These are the SAME for all images from the      │
│     same model version (model-level key)            │
│                                                     │
│  3. Neural network encoder adds a learned noise     │
│     pattern that embeds these carrier phases        │
│     into the image without visible artifacts        │
│                                                     │
├─────────────────────────────────────────────────────┤
│             Detection (what we do)                  │
├─────────────────────────────────────────────────────┤
│                                                     │
│  1. Resize image to 512x512                         │
│  2. Compute 2D FFT (Fast Fourier Transform)         │
│  3. Check phase values at known carrier bins        │
│  4. Compare magnitude at carriers vs background     │
│  5. If phases match expected values → watermarked   │
│                                                     │
└─────────────────────────────────────────────────────┘
```

The key insight is that the watermark lives in the **frequency domain**, not the spatial domain. A regular photo has essentially random phase values at any given frequency bin. A SynthID-watermarked image has **specific, predictable phase values** at specific frequency coordinates — and those phases are consistent across every image generated by the same model.

## Reverse Engineering: The Spectral Codebook

Research by [aloshdenny/reverse-SynthID](https://github.com/aloshdenny/reverse-SynthID) analyzed 250 Gemini-generated images and discovered:

### Carrier Frequencies

The watermark uses specific carrier frequencies with extremely high phase coherence (>99.9%):

| Frequency (fy, fx) | Coherence | Magnitude | Phase (radians) |
|---------------------|-----------|-----------|-----------------|
| (14, 14)            | 0.9996    | 16807     | -1.4409         |
| (-14, -14)          | 0.9996    | 16807     | 1.4409          |
| (126, 14)           | 0.9996    | 8046      | -2.3736         |
| (-126, -14)         | 0.9996    | 8046      | 2.3736          |
| (98, -14)           | 0.9994    | 6283      | 0.6109          |
| (-98, 14)           | 0.9994    | 6283      | -0.6109         |
| (210, -14)          | 0.9996    | 6032      | 1.1315          |
| (-210, 14)          | 0.9996    | 6032      | -1.1315         |
| (238, 14)           | 0.9990    | 4190      | -1.6099         |
| (-238, -14)         | 0.9990    | 4190      | 1.6099          |

**Pattern:** Most carriers lie along or near the fy=±14 horizontal line in frequency space, suggesting a structured frequency selection algorithm. Carriers appear in conjugate pairs (symmetry), which is expected for a real-valued signal.

### Why Phase Coherence Matters

"Phase coherence" measures how consistent the phase value is across many different images at the same frequency bin:
- **1.0** = identical phase in every image (perfect watermark signal)
- **0.5** = random (no watermark)
- **0.0** = perfectly anti-correlated

Natural (non-watermarked) images have essentially random phase at any given frequency bin. Finding 10 bins with >0.999 coherence is astronomically unlikely by chance.

## Our Detection Algorithm

The extension uses **Tier A: Raw FFT phase + annular magnitude ratio** — the simplest approach that achieves 0 false positives.

### Step by Step

1. **Center-crop to square**: If the image is non-square, take the largest centered square crop. This preserves the watermark's spatial frequency relationships better than stretching.

2. **Resize to 512x512**: The carrier frequencies were measured at this resolution. The 2D FFT size must match for the frequency bin coordinates to align.

3. **Convert to grayscale**: ITU-R BT.601 luma: `0.299R + 0.587G + 0.114B`

4. **Compute 2D FFT**: Radix-2 Cooley-Tukey algorithm (512 = 2^9), then fftshift to center DC.

5. **Phase check**: At each of the 10 carrier frequency bins, compute the circular phase difference between the actual phase and the expected phase from the codebook. Normalize to a 0–1 match score where 1.0 = perfect match:
   ```
   match = 1 - |atan2(sin(actual - expected), cos(actual - expected))| / pi
   ```
   A carrier is "matched" if its score exceeds 0.7 (±54° tolerance).

6. **Annular magnitude ratio**: For each carrier bin, sample 24 points around a ring at the same radius (same distance from DC) but different angles. Compare the carrier's magnitude to the median of these ring samples. A watermarked carrier will have significantly higher magnitude than its neighbors on the ring.

7. **Detection decision** (three paths, any triggers detection):
   - **Strong**: 8+ of 10 carriers phase-matched AND average magnitude ratio > 5x → high confidence (0.80–0.95)
   - **Moderate**: 6+ carriers matched AND average phase > 0.55 AND magnitude ratio > 3x → moderate confidence (0.45–0.75)
   - **Phase-strong**: 6+ carriers with >0.9 phase match (strict) AND average phase > 0.75 → high confidence. This path catches content-rich images where the watermark magnitude doesn't stand out above natural image frequencies, but the phase alignment is unmistakable.

### Implementation

The algorithm is implemented in pure JavaScript in `synthid-detect.js` (~390 lines, zero dependencies). It uses:
- Hand-rolled radix-2 Cooley-Tukey FFT (1D, applied row-then-column for 2D)
- Canvas API to resize and extract pixel data
- `window.__acsSynthID.detectSynthIDWatermark()` as the public interface

## Test Images

### Watermarked Images (Expected: detected)

#### `synthid_black.jpg` — Pure black generated by Gemini with SynthID
A 1024x1024 solid black image generated through Google Gemini. Despite having no visible content, the watermark is clearly present in the frequency domain. This is the strongest test case — the watermark signal dominates because there's no image content to compete with.

- **Result**: Detected (strong). Phase match: 0.974. Magnitude ratio: 63.7x. All 10/10 carriers matched.

#### `synthid_white.jpg` — Pure white generated by Gemini with SynthID
Same concept as the black image, 1024x1024 solid white from Gemini. The watermark signal is strong but slightly weaker than the black image due to the higher baseline pixel values affecting the FFT magnitude spectrum.

- **Result**: Detected (strong). Phase match: 0.940. Magnitude ratio: 21.0x. All 10/10 carriers matched.

#### `synthid_watermark.png` — Extracted watermark visualization (512x512)
A visualization of the SynthID watermark pattern itself, extracted through noise residual analysis. This is the watermark "fingerprint" — the pattern that gets added to every Gemini image. Already 512x512, no resizing needed, which gives the cleanest frequency alignment.

- **Result**: Detected (strong). Phase match: 0.930. Magnitude ratio: 27.3x. All 10/10 carriers matched.

#### `sample_watermarked.png` — Real Gemini-generated photo (768x1365)
A real AI-generated portrait photo from Gemini at 768x1365 resolution (non-square, portrait aspect ratio). This is the hardest test case: the image has complex natural-looking content, is non-square (requiring center-crop), and the watermark must compete with actual image frequency content.

- **Result**: NOT detected by Tier A (false negative). Phase match: 0.563. Only 6/10 carriers matched. Magnitude ratio: 0.89x (watermark signal not above background). The non-square aspect ratio means center-cropping discards significant portions of the image, and the remaining portion's natural content masks the watermark's magnitude signature. Tier B and C detect this image because they use noise-domain analysis which isolates the watermark from image content, but at the cost of more false positives.

### Control Images (Expected: not detected)

#### `sample_cleaned.png` — Watermark-removed version (1208x2152)
The same subject as `sample_watermarked.png` but processed through a watermark removal tool. This is a critical test: does any residual watermark signal survive removal?

- **Result**: Not detected by Tier A. Phase match: 0.718 (somewhat elevated — residual signal exists). But magnitude ratio: 1.82x (below the 2.0 threshold). The removal tool degraded the watermark enough that the magnitude anomaly disappears, even though some phase alignment remains. Tiers B, C, and D falsely detect this as watermarked because their thresholds are looser.

## Detection Tiers Tested

Four detection approaches were evaluated, from simplest to most complex:

### Tier A: Raw FFT Phase + Annular Magnitude
- **Method**: FFT the raw grayscale image. Check phase at carriers. Compare carrier magnitude to same-radius ring median.
- **Speed**: ~2ms (Python), estimated 5-15ms in JS
- **JS-portable**: Yes — Canvas + pure JS FFT
- **Dependencies**: None

### Tier B: Gaussian Highpass + FFT
- **Method**: Subtract a Gaussian blur (sigma=4, kernel=15) from the image to isolate high-frequency noise. FFT the residual. Check phase + noise structure ratio.
- **Speed**: ~2ms (Python)
- **JS-portable**: Yes — would need Canvas-based blur or JS convolution
- **Dependencies**: None (but more code)

### Tier C: Wavelet Denoise + FFT
- **Method**: Apply db4 wavelet decomposition (3 levels) with soft thresholding to extract noise residual. FFT the noise. Check phase + structure ratio.
- **Speed**: ~20ms (Python)
- **JS-portable**: No — requires a wavelet library
- **Dependencies**: PyWavelets

### Tier D: Combined A + B Vote
- **Method**: Run both Tier A and Tier B. Detect if either shows strong confidence or both agree.
- **Speed**: ~4ms (Python)
- **JS-portable**: Yes
- **Dependencies**: None

## Why Tier A Was Chosen

Tier A was selected for the Chrome extension (`synthid-detect.js`) for these reasons:

### 1. Zero false positives
This is the most important metric for a browser extension. A false positive means incorrectly telling a user that a normal photo is AI-generated, which destroys trust. Tier A is the **only tier with 0 FP** across all test images.

### 2. The magnitude ratio is the key discriminator
The breakthrough insight from testing: phase matching alone is insufficient. Several control images (`landscape`, `texture`, `face_shapes`) achieve phase match scores of 0.6-0.7 and 4-6/10 carriers "matched" — purely by chance. What separates watermarked from non-watermarked images is the **annular magnitude ratio**:

| | Watermarked (detected) | Controls (not detected) |
|---|---|---|
| Magnitude ratio | 21x – 64x | 0.0x – 1.4x |

There is a clear 15x+ gap between the weakest detected watermark (21x) and the strongest control (1.4x). This makes the magnitude ratio an extremely reliable discriminator.

### 3. Fastest execution
At ~2ms in Python, Tier A is the fastest approach. In JavaScript running in a browser, this translates to an estimated 5-15ms per image — acceptable for scanning a page with dozens of images.

### 4. Simplest implementation
Tier A requires only:
- 2D FFT (pure JS, ~100 lines)
- Phase comparison (5 lines)
- Annular ring magnitude comparison (15 lines)

No external dependencies. No blur kernels. No wavelet transforms. This is critical for a Chrome extension where bundle size and simplicity matter.

### Multi-crop strategy

For non-square images, the detector tries multiple 512x512 crops to maximize the chance of preserving the watermark signal:
1. **Center-square resize**: Crop the largest centered square, then resize to 512x512
2. **Center-direct**: Take a direct 512x512 crop from the center (no resize)
3. **Edge crop**: Take a 512x512 crop from the bottom or right edge

Detection succeeds if any crop produces a strong match, with early exit when confidence > 0.9.

### 5. The one false negative is acceptable
The single missed image (`sample_watermarked.png`) is a 768x1365 portrait that loses its watermark signal when center-cropped and squeezed to 512x512. This is an inherent limitation of frequency-domain analysis: aggressive non-uniform scaling destroys the carrier frequency alignment. Real-world Gemini images are typically square or near-square (1024x1024, 1536x1536), where this isn't an issue.

### Why not Tier B or C?
Despite catching the difficult `sample_watermarked.png`, Tiers B and C produce too many false positives (4-6 out of 9 non-watermarked images). The noise-domain analysis they perform is better at isolating the watermark signal, but the structure ratio threshold (0.8-2.0) is too broad — many natural images have noise structure ratios in that range.

### Why not Tier D?
The combined vote reduces FPs compared to B alone, but still has 2 FPs. The added complexity of running two analysis passes isn't justified when Tier A alone achieves 0 FP.

## Detection Signal Hierarchy

SynthID is one of several detection signals used by the extension. Each signal carries a confidence weight, and signals are combined using independent probability:

```
combined = 1 - ∏(1 - wᵢ)
```

### Signal Weights

| Priority | Signal | Weight | Type | Survives stripping? |
|----------|--------|--------|------|---------------------|
| 1 | C2PA (AI tool) | 0.99 | First-party cryptographic attestation | No — trivially removable |
| 2 | SynthID | 0.98 | Pixel-level watermark (spectral analysis) | Yes — survives re-encoding, cropping, screenshots |
| 3 | IPTC DigitalSourceType | 0.92 | Standard metadata field | No |
| 4 | EXIF/XMP AI signature | 0.90 | Tool name in metadata | No |
| 5 | URL pattern | 0.65 | Circumstantial (AI service domain) | N/A |
| 6 | Alt text | 0.55 | Circumstantial (DOM text) | N/A |

### Why C2PA outranks SynthID

When C2PA is present with an AI tool signature, the generating tool itself is declaring "I made this" with cryptographic provenance — a first-party attestation of origin. SynthID, while extremely reliable, is detected through reverse-engineered spectral analysis — a third-party observation. The distinction:

- **C2PA AI**: The tool signed a statement saying "I generated this" → certainty of origin
- **SynthID**: We detected a watermark pattern consistent with known carriers → high confidence but inferred

However, SynthID is far more **robust** than C2PA. C2PA metadata can be stripped by saving, re-encoding, or screenshotting the image. SynthID survives all of these. In practice, SynthID will fire on many images where C2PA has been removed.

### Verdict Priority

The extension assigns one of five verdicts to each scanned item. Verdicts follow a strict priority — a stronger verdict can never be downgraded by a weaker signal:

```
no_metadata (0) < likely_real (1) < uncertain (2) < likely_ai (3) < ai_detected (4)
```

This prevents edge cases like:
- C2PA camera detection (`likely_real`) overwriting a SynthID detection (`ai_detected`)
- An alt text miss resetting a metadata-confirmed verdict

Each signal can only **upgrade** the verdict. For example, if SynthID sets `ai_detected` and then C2PA detects a camera signature, the verdict stays `ai_detected` — the watermark evidence outweighs the camera provenance claim.

### Reason Display Order

When multiple signals fire, the popup displays reasons sorted by signal strength (strongest first):

1. C2PA Content Credentials (AI tool)
2. SynthID watermark detection
3. IPTC DigitalSourceType
4. EXIF/XMP AI tool signature
5. URL pattern match
6. Alt text match

This ensures the most definitive evidence is always visible first in the collapsed result view.

### Combined Score Examples

| Signals present | Confidence | Verdict |
|-----------------|------------|---------|
| C2PA AI only | 99% | ai_detected |
| SynthID only | 98% | ai_detected |
| C2PA AI + SynthID | 99% | ai_detected |
| EXIF + IPTC | 99% | ai_detected |
| SynthID + EXIF | 99% | ai_detected |
| URL pattern only | 65% | likely_ai |
| Alt text only | 55% | likely_ai |
| URL + alt text | 84% | likely_ai |
| SynthID + URL + alt text | 99% | ai_detected |
| No signals | 5% | no_metadata |

## Known Limitations

1. **Gemini/Imagen only**: The codebook only covers SynthID as embedded by Google's image generators. Other AI tools (DALL-E, Midjourney, Stable Diffusion) use different watermarking schemes or none at all.

2. **Non-square images**: Images with extreme aspect ratios (>2:1) may lose the watermark signal after center-cropping and resizing. The watermark is distributed uniformly across the image, so discarding large portions removes proportional watermark energy.

3. **Small images**: Images below 128x128 are skipped entirely. The watermark requires sufficient spatial resolution for the carrier frequencies to be representable in the FFT.

4. **Heavy post-processing**: Multiple rounds of JPEG compression, aggressive noise addition, or re-rendering through another generative model can destroy the watermark. This is a known limitation documented by Google themselves.

5. **Codebook staleness**: If Google changes SynthID's carrier frequencies or phase values in a future model version, images from that version won't be detected until a new codebook entry is added.

6. **CORS constraints**: The detector needs pixel data, which means the image bytes must be fetchable. The extension handles this via its background worker CORS proxy (`FETCH_IMAGE` message), passing the `ArrayBuffer` to the detector.

## Versioning and Future-Proofing

The codebook is structured as a versioned array in `synthid-detect.js`:

```javascript
const CODEBOOKS = [
  {
    id: "gemini-v1",
    label: "Gemini / Imagen (2024-2025)",
    carriers: [
      { fy: -14,  fx: -14,  phase:  1.4409 },
      // ... 9 more carriers (conjugate pairs)
    ],
    thresholds: {
      strongPhaseMatched: 8,     // 8/10 carriers at >0.7 match
      strongMagRatio: 5.0,       // carrier magnitude 5x ring median
      moderatePhaseMatched: 6,   // 6/10 carriers at >0.7 match
      moderatePhaseAvg: 0.55,    // average phase score
      moderateMagRatio: 3.0,     // carrier magnitude 3x ring median
      phaseStrongMatched90: 6,   // 6/10 carriers at >0.9 match (strict)
      phaseStrongAvg: 0.75,      // average phase for phase-strong path
      phaseMatchCutoff: 0.7,     // threshold for "matched" carrier
      phaseMatchCutoffStrict: 0.9, // strict threshold for phase-strong path
    },
  },
  // Future codebook versions go here
];
```

When Google updates SynthID:
1. Researchers extract new carrier frequencies from the updated model's outputs
2. A new codebook entry is added to the `CODEBOOKS` array
3. Old entries remain — the detector tests all codebook versions and returns the best match
4. This is a **data-only update** — no algorithm changes needed

## Running the Tests

```bash
# Create a virtual environment
python -m venv .venv
source .venv/bin/activate   # Linux/Mac
# .venv\Scripts\activate    # Windows

# Install dependencies
pip install numpy scipy opencv-python-headless PyWavelets

# Run from the repo root
python tests/synthid/smoke_test.py
```

The test script:
- Loads watermarked images from `tests/synthid/watermarked/`
- Loads control images from `tests/synthid/controls/`
- Generates 8 additional synthetic control images in `tests/synthid/controls/generated/`
- Runs all 4 detection tiers
- Reports accuracy, false positive/negative rates, and timing
- Exits with code 0 if Tier A has 0 false positives, code 1 otherwise

### Adding Test Images

To add more test images:
- **Watermarked**: Place Gemini/Imagen-generated images in `tests/synthid/watermarked/`
- **Controls**: Place non-watermarked images in `tests/synthid/controls/`
- Re-run the test — it auto-discovers images by file extension (`.png`, `.jpg`, `.jpeg`, `.webp`)
